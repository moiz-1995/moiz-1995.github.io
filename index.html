Approach

How I decide automation can be trusted

Scripts first, models last

A deterministic step is cheaper and repeatable. I use a language model where a page is unknown or changes, and never to produce a figure nobody checks.

Read back everything

A field that was typed is not a field that was saved. Each value is read from the page, and from the network when it matters, before the next step runs.

A passing test is not evidence

I score from the system's own record of what happened, and add guards so a run that tested nothing can never pass.

Show the client

I demo after every iteration and turn what I hear into user stories. Most rework is a misunderstanding a demo would have caught.

Research

How reliable are browser agents?

webagent-bench runs the same insurance-quote tasks through four setups on five simulated portals, two of them held out, and scores each run from the portal's own record of what it received. Preliminary pilot results, for a paper in preparation:

Playwright script
95%
Stagehand scripted
45%
Stagehand agent
26%
Browser Use
0–4%
Correct-quote rate on development portals, baseline condition. Playwright n = 104. Under UI changes and injected faults, every setup drops sharply, which is the point of the study.

My MS thesis built CAQI, a 20-indicator index for how well Scrum teams run their ceremonies. In a pilot on a live team's sprint artefacts, reviewers using it scored 14.25 against 11.25 for unguided reviewers (p = 0.004) in the same time.
